# 01 Product Requirements Document (PRD)

## 1. Product Overview
The **TrustLens AI Platform** provides real-time, explainable web intelligence. It evaluates websites using a multi-dimensional scoring model (Security, Privacy, Web3, Trust) and delivers actionable recommendations. The primary client is a Browser Extension, backed by a scalable API, Threat Intelligence Engine, and Machine Learning Engine.

## 2. Target Audience & User Personas
### 2.1. The Cautious Consumer (Alice)
- **Profile:** Not deeply technical, but aware of online scams.
- **Pain Point:** Doesn't understand technical browser warnings. Wants to know if a site is safe for shopping.
- **Need:** Simple, clear warnings generated by the Decision Engine, with human-readable explanations.

### 2.2. The Privacy Advocate (Bob)
- **Profile:** Tech-savvy, values data privacy, uses ad-blockers.
- **Pain Point:** Hates reading privacy policies and wonders who is tracking him.
- **Need:** Detailed breakdown of trackers from the Privacy Intelligence Engine and AI-summarized privacy policies.

### 2.3. The Web3 Pioneer (Charlie)
- **Profile:** Actively trades crypto and mints NFTs.
- **Pain Point:** High risk of wallet drainers and malicious smart contracts.
- **Need:** The Web3 Engine plugin to analyze wallet connection requests and contract reputation.

### 2.4. The Enterprise IT Admin (Diana) - *Future Scope*
- **Profile:** Manages fleet of employee devices.
- **Need:** Enterprise APIs and aggregated dashboard of threats encountered by employees.

## 3. User Stories
### Epic 1: Multi-Dimensional Scanning Pipeline
- As a user, I want the Data Collection Engine to automatically extract site features without slowing my browsing.
- As a user, I want to see distinct scores for Security, Privacy, and Overall Trust.
- As a Web3 user, I want a specialized Web3 Score to appear only on crypto-related websites.

### Epic 2: Explainability & Decision Making
- As a user, I want the Decision Engine to interpret the scores and give me a definitive "Safe" or "Dangerous" recommendation.
- As a user, I want the Explainability Engine to translate technical findings (e.g., from the Machine Learning Engine) into plain English.
- As a user, I want a Confidence Score so I know how certain the AI is about its recommendation.

### Epic 3: Community & Knowledge Base
- As a user, I want to report a false positive to the Community Intelligence Engine.
- As a user, I want to view detailed definitions of threat categories (e.g., Credential Theft, Fake Login) sourced from the Knowledge Base.

## 4. Functional Requirements
### 4.1. Core Platform Pipeline
- **REQ-PLT-01:** The platform must implement a sequential Analysis Pipeline (Data Collection -> Feature Extraction -> Sub-Engines -> Fusion -> Decision).
- **REQ-PLT-02:** The architecture must support a Plugin Manager to easily toggle engines (e.g., Web3 Engine).

### 4.2. Browser Extension Client
- **REQ-EXT-01:** Must trigger on web navigation events and act as the Data Collection Engine client.
- **REQ-EXT-02:** Must display the timeline of the Analysis Pipeline (e.g., "URL Analyzed", "SSL Verified").
- **REQ-EXT-03:** Must visually represent all scores and the Confidence metric.

### 4.3. Engines & Backend
- **REQ-ENG-01:** Must separate deterministic logic (Rule Engine) from probabilistic logic (Machine Learning Engine).
- **REQ-ENG-02:** Must isolate all third-party API calls into the Threat Intelligence Engine.
- **REQ-ENG-03:** Must merge all engine outputs systematically via the Score Fusion Engine.

## 5. Non-Functional Requirements
- **Performance:** Feature Extraction and Rule Engine evaluation must complete in < 50ms. End-to-end scanning < 2000ms.
- **Scalability:** Microservices or modular monolith design to allow independent scaling of the Machine Learning Engine.
- **Security:** Data collection must anonymize DOM contents.
